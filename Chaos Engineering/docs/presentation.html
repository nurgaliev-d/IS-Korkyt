02 / 10ПРОБЛЕМА

Неге бұл маңызды?

  • Микросервистер желі арқылы бір-біріне тәуелді.
  • Бір сервис баяуласа, қалғандарына да әсер етуі мүмкін.
  • Нәтижесі — cascade failure, яғни бүкіл жүйенің тоқтауы.
  • Кәдімгі тесттер production-дегі latency, packet loss, overload-ты толық тексермейді.
03 / 10ӘДІСНАМА

Chaos Engineering деген не?

Жүйеге қауіпсіз, бақылаулы ортада әдейі ақау енгізіп, төзімділігі туралы гипотезаны тексеру әдісі.

HYPOTHESIS → INJECT FAULT → OBSERVE → LEARN → IMPROVE

Мақсаты — жүйені сындыру емес, шынайы ақауға алдын ала дайын болу.

06 / 10СЦЕНАРИЙЛЕР

Chaos эксперименттері

  • Latency injection: Payment сервисіне +1500 ms кідіріс.
  • Pod failure: Inventory replica-сының істен шығуы.
  • Network loss: Gateway → Order жолында 30% packet loss.
  • Traffic overload: кіріс трафигін 5 есе арттыру.
07 / 10ҚОРҒАНЫС

Resilience механизмдері

Timeout

Ұзақ күткен сұранысты тоқтатады.

Retry + backoff

Уақытша қатені қауіпсіз қайта орындайды.

Circuit breaker

Қате тәуелділікке шексіз сұранысты бөгейді.

Fallback + autoscaling

Балама жауап береді, жүктемеде replica санын өсіреді.

08 / 10ДЕМОНСТРАЦИЯ

ResiliLab қалай жұмыс істейді?

  1. Baseline метрикаларын көрсетемін.
  2. Бір fault injection сценарийін қосамын.
  3. Сервис статусы, график және Experiment log өзгерісін бақылаймын.
  4. SLO мен қорғаныс механизмін түсіндіремін.
  5. Reset арқылы recovery-ді көрсетемін.
09 / 10НӘТИЖЕ

Жобаның құндылығы

  • Әлсіз жерлерді production-ға жетпей анықтайды.
  • Қорғаныс механизмдерінің нақты әсерін өлшейді.
  • Командаға SLO және error budget туралы шешім қабылдауға көмектеседі.
  • Жүйені «істен шықпайтын» емес, «жылдам қалпына келетін» етеді.
10 / 10ҚОРЫТЫНДЫ

Негізгі ой

Fault tolerance — тек replica саны емес. Ол observability, SLO, timeout, retry, circuit breaker және graceful degradation үйлесімі.

Chaos Engineering осы қасиеттерді шынайы ақаудан бұрын дәлелдеуге мүмкіндік береді.
