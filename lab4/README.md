# №4 зертханалық жұмыс: ORM өнімділігі, аналитика және тұтастық

Бұл Django жобасы үш зертханалық бөлімнің барлық тәжірибелік тармақтарын бір жерде орындайды. Интерфейс, консольдік хабарламалар және түсіндірмелер қазақ тілінде берілген.

## Іске қосу

PowerShell терезесінде осы бумаға өтіп, төмендегі пәрмендерді орындаңыз:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_data
```

`seed_data` 100 автор, 1 000 кітап, 20 бөлім және 12 000 қызметкер жасайды. Осы көлем N+1 және аналитикалық тәжірибелер үшін жеткілікті.

## 1-бөлім — N+1 мәселесі және SQL журнал

```powershell
python manage.py benchmark_nplusone
```

Команда екі жағдайды өлшейді:

| Нұсқа | Код идеясы | Күтілетін SQL саны |
| --- | --- | --- |
| Анти-паттерн | `Book.objects.all()` циклінде `book.author.name` оқу | 1 001 |
| Оңтайландыру | `Book.objects.select_related("author")` | 1 |

Неге 1 001? Алғашқы сұраныс 1 000 кітапты алады, ал авторға әр қолжеткізу оған жеке сұраныс жібереді. `select_related` `JOIN` қолданады да, кітап пен авторды бір сұраныспен әкеледі.

`settings.py` файлында `django.db.backends` журналы қосылған; сондықтан консольден SQL мәтіні көрінеді. Есепке терминалдың N+1 және `select_related` нәтижелерін скриншот етіп салыңыз.

## 2-бөлім — Күрделі аналитика: ORM және таза SQL

Таңдалған есеп: әр бөлімдегі жалақысы ең жоғары үш қызметкерді, бөлімнің орташа жалақысын және айырмасын шығару. Ол `PARTITION BY`, `DENSE_RANK()`, `AVG() OVER` және сыртқы сүзгіні пайдаланады.

```powershell
python manage.py benchmark_analytics
```

Команда мыналарды басып шығарады:

- ORM нұсқасының уақыты және шыңдық жад тұтынуы;
- таза SQL нұсқасының уақыты және шыңдық жад тұтынуы;
- Django генерациялаған SQL және қолмен жазылған SQL.

ORM коды `analytics/management/commands/benchmark_analytics.py` ішінде `orm_query()` функциясында, ал таза SQL сол файлдағы `RAW_SQL` айнымалысында сақталған. ORM нұсқасы қысқа әрі модель өзгергенде қауіпсіз. Бірақ өте күрделі есепте таза SQL оқылуы жеңіл, нақты SQL пішінін басқаруға мүмкіндік береді. Нақты уақыт айырмасы деректер базасы мен жабдыққа тәуелді; есепке өзіңіздегі өлшемдерді жазыңыз.

## 3-бөлім — Транзакциялар, миграция және жаппай енгізу

### Құлыптау

`analytics/services.py` файлында екі тәсіл бар:

- `pessimistic_raise()` — `select_for_update()` арқылы жолды пессимистік құлыптайды;
- `optimistic_raise()` — `version` өрісін тексеріп, бәсекелес жаңартуды анықтайды.

SQLite оқу нұсқасында `select_for_update()` жолдық құлыптауды іске асырмайды. Нақты параллель тест пен оқшаулау деңгейлері үшін PostgreSQL пайдаланыңыз. PostgreSQL-де `READ COMMITTED`, `REPEATABLE READ` не `SERIALIZABLE` деңгейлерін қосылым баптауымен тағайындап, екі бөлек сессияда бір қызметкердің жалақысын қатар өзгертіңіз. Нұсқасыз оқу-өзгерту-жазу әрекеті **Lost Update** тудырады; екі берілген функция оны болдырмайды.

### Миграция аудиті

Бастапқы миграция: `analytics/migrations/0001_initial.py`.

```powershell
python manage.py sqlmigrate analytics 0001
```

Шығысынан `FOREIGN KEY` байланыстарын және `кітап_автор_жыл`, `қызметкер_бөлім_жалақы` индекстерін көресіз. `ForeignKey` өрісі Django тарапынан да индекстеледі.

### 20 000 жазбаны енгізу

```powershell
python manage.py benchmark_bulk
```

Команда бірдей 20 000 қызметкерді әуелі циклдегі `save()` арқылы, содан соң `bulk_create()` арқылы сақтайды. Ол уақытты миллисекундпен және жеделдету еселігін шығарады. Әдетте `bulk_create()` айтарлықтай жылдам, өйткені ол жеке `INSERT` командаларын азайтады. Бұл әдіс `save()` әдісінің жеке логикасы мен сигналдарын шақырмайтынын қорытындыда ескеріңіз.

## Есепке арналған қысқа құрылым

1. Орта: Python, Django, ДБ түрі, компьютердің негізгі сипаттамасы.
2. 1-бөлім: N+1 және `select_related` командаларының экран суреттері, SQL саны мен уақыт кестесі.
3. 2-бөлім: ORM SQL және қолмен SQL, уақыт пен RAM кестесі, оқылымдылық/тиімділік талдауы.
4. 3-бөлім: `sqlmigrate` нәтижесі, индекс пен сыртқы кілттер түсіндірмесі, `save()`/`bulk_create()` кестесі, жарыс жағдайы мен екі құлыптау тәсілінің талдауы.
5. Қорытынды: қарапайым CRUD және байланыстар үшін ORM тиімді; ерекше терезелік функциялар, ДБ-ға тән кеңейтімдер, өте күрделі CTE немесе дәл орындалу жоспарын бақылау керек болғанда таза SQL орынды.

## Қосымша: шағын веб-бет

```powershell
python manage.py runserver
```

Браузерден `http://127.0.0.1:8000/` адресін ашыңыз. Бет деректер қорының ағымдағы санағыштарын көрсетеді.
